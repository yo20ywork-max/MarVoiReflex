# MVP：這 16 週先完成哪些事

MVP 就是「最小但完整、可以讓人實際試用的版本」。本次只做行銷素材整理。

| 核心功能 | 使用者會看到什麼 | 現有狀態／驗收條件 |
|---|---|---|
| 開指定工具 | 說「開瀏覽器和活動資料夾」 | **待開發**；只允許設定好的程式與授權路徑，不開任意執行檔／網址 |
| 搜尋與分類 | 輸入活動名稱、圖片／文案、本週／起迄日期 | 已有受限版本；選到的檔案必須與人工標準答案相同 |
| 預覽與確認 | 顯示每個來源、目的地、數量；按確認才搬移 | 已有；預覽／取消原檔不變；同名檔停止；搬後逐一核對 |

## 現有功能的邊界

- 匯入：PNG、JPG、JPEG、WEBP、TXT、MD；單檔最多 32MB。PDF、Word、Excel、影音不屬本版支援類型。
- 工作區：只處理 App 的 `workspace/materials`。不掃全機、不直接整理使用者任意硬碟路徑。
- 活動名稱：優先明確寫出「秋季促銷」等檔名關鍵字；不做圖片視覺內容辨識。成效截圖是圖片；要單獨辨認成效截圖需靠檔名關鍵字，非看圖理解。
- 精確副檔名：目前按圖片／文字兩大類篩選，尚未保證PNG-only、JPG-only、MD-only；這是50題M13–M15與Issue的待補項目，不能默默放寬成整類。
- 日期：以檔名中的 `YYYYMMDD` 為準；本週是當地日期所屬週一至週日，含起迄日。不是檔案修改時間、拍攝時間或 EXIF。沒有可讀日期的檔案不會被本週條件選入。
- 分類去向固定為 `materials/已整理/圖片/` 與 `materials/已整理/文案/`。依活動／週別另建多層資料夾屬後續待開發規格，不宣稱已完成。
- 需移動的操作先產生計畫 ID 與檔案雜湊；只有畫面確認能執行。口頭說「同意」不算按鍵確認。
- 刪除、複製、覆寫、排序與模糊日期會拒絕或要求說清楚。執行失敗可能留下已完成的部分搬移，應回報實際狀態，**不保證整批自動回復**。

## 三個階段

1. 指定 App 啟動、資料夾搜尋、檔案清單。清單／受限搜尋已有，App 啟動待補。
2. 類型分類、移動前預覽、畫面確認、結果驗證、取消及錯誤回報。
3. 中文語音、可檢查的多步驟規劃與錯誤處理；擴大口語測試，補齊 8GB 無獨顯實機驗證。

## 不列入本次驗收

自動發文、生成行銷文案、跨平台登入與帳號操作，放在未來擴充。語音聊天已是介面功能，但不拿它代替核心素材任務的完成證據。

## 一次完整任務的驗收例

先匯入固定測試素材 → 在任務模式輸入「整理本週的圖片與文案，先給我預覽」→ 核對檔案與目的地 → 按確認 → 檢查內容雜湊不變、來源消失、目的檔存在、結果摘要與紀錄一致。另跑取消／同名檔／越界案例。
